# Sigurnosni status

Granularne provjere i eksplicitni Manager/Payments API UAT su opisani u `GRANULAR_PERMISSIONS.md`. `Deny` na `BankAccounts.Create` ili `BankStatements.Import` odbija direktni API poziv i kada role default dopušta akciju. `Owner` ne može pozvati osoblje/tenant-wide endpoint čak ni sa ručnim funkcionalnim grantom; vidljivost konkretnih dokumenata i finansijskih zapisa ostaje zasebna provjera. Nije izvršen penetration test.

Backend čita uloge/članstva iz baze; tenant/ZEV scope provjerava server. Refresh token se čuva hashiran, lozinka hashirana, upload ima limit 5 MB, MIME/magic-byte i provjeru ekstenzije, nasumični storage key i endpoint autorizaciju. Finansijski knjiženi zapisi imaju append-only zaštitu u EF sloju. Ovo nije penetration test niti garancija protiv direktnog SQL pristupa.

Reset lozinke preko `POST /api/system/users/{id}/reset-password` može izvršiti samo System Administrator; samo frontend skrivanje nije zaštita. Kreiranje korisnika, reset i samostalna promjena koriste `PasswordPolicy` (`PasswordPolicy:MinimumLength`, minimalno 12; `MaximumLength`, podrazumijevano 256; veliko/malo slovo, broj, specijalni znak). Lozinku hashira postojeći ASP.NET Core `PasswordHasher<AppUser>`; API ne vraća hash ili plaintext. Admin bira obaveznu promjenu pri sljedećoj prijavi. Tada je JWT ograničen na `/api/me` i rute za promjenu lozinke, a refresh je odbijen do promjene. Normalni self-service traži trenutnu lozinku; nakon promjene web dobija novi token/HttpOnly cookie, a mobilna aplikacija novi access/refresh token za SecureStore. Svaki reset/promjena povisuje `SecurityVersion`, opoziva postojeće refresh sesije i odmah obara stare access JWT-e; dodatna verzija na refresh sesiji sprječava i trku pri rotaciji. Audit bilježi aktera/cilj/korelaciju bez lozinke ili hasha. UAT koraci su u `PASSWORD_MANAGEMENT_UAT.md`.

Od 30.09.2026. `EffectiveAccessService` računa SYSTEM/ORG/ZEV/OWNERSHIP/MANUAL_OVERRIDE izvore, s `Deny` prioritetom osim System Administratora. `Person.UserId` bez `Verified` ne daje owner pristup. Novi ručni Owner membership je zabranjen, a naslijeđeni red ne daje pristup ni Owner-role sadržaju. Ugovor/private person/charge/payment ID se dodatno provjeravaju server-side; `ZevMembers` dokument je zajednički, `PersonOnly`/`PropertyUnit` privatan, `ManagersOnly` interni. Direktni file ID ne preskače dokument permission. Verifikacija, override, promjena dokument vidljivosti, osjetljivi download i finansijski PDF/XLSX export su auditirani. `Privacy:HistoricalSelfAccess` je false po defaultu; ograničeni istorijski self-finance nije novo ZEV čitanje. Detalji i UAT su u `ACCESS_CONTROL_AND_PRIVACY.md` i `OWNER_ACCESS_UAT.md`.

Ovo nisu potvrđeni retencijski rokovi, zakonita osnova obrade, subject export ili workflow anonimizacije. Ne označavati sistem „GDPR compliant“ bez pravnog/poslovnog odobrenja i stvarnog UAT-a na migriranoj bazi.

Provjerene regresije uključuju owner finance/tuđu uplatnicu, raw document IDOR, manager cross-ZEV registar/izvještaj, neaktivno članstvo, refresh replay, pogrešnu ekstenziju, prevelik upload i potpis datoteke. U produkciji dodatno provjeriti svaki endpoint, rate limit po ulozi, revokaciju sesije, rotaciju JWT ključa, TLS/HSTS/CORS, antivirus/file scanning, log redakciju, storage ACL i centralizovani audit.

Dependency status: web npm audit 0, mobile 23 moderate, NuGet scan NOT VERIFIED zbog `NU1900`/nedostupnog feeda. Tabela paketa je u `DEPENDENCY_SECURITY_STATUS.md`. Mobile runtime na uređaju nije provjeren. Četiri SQL race scenarija prolaze u izolovanim testovima; bankarski povrat/reversal i širi load/soak test ostaju otvoreni. Dok se oni i poslovno/pravno odobrenje ne riješe, ne označavati sistem Production Ready.
